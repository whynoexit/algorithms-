Complexity — Оценка сложности

1. Как называется

Оценка сложности алгоритма — временной и по памяти.

2. Что вообще делает

Помогает ещё до написания кода прикинуть: успеет ли программа отработать за разумное время и не сожрёт ли она всю память.

Главный инструмент тут — Big O:

O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), ...

3. Когда вспоминать

Когда в условии большое n и надо понять:

«А мой алгоритм вообще успеет?»

4. Как узнать, что оно в задаче

Первым делом смотрим на ограничения.

Например:

n <= 20
→ можно спокойно писать O(2ⁿ), иногда даже O(n!)

n <= 1000
→ O(n²) вполне прокатит.

n <= 2 * 10⁵
→ нужен примерно O(n log n) или O(n).

n <= 10⁹
→ тут O(n) уже много, обычно ищем формулу, бинарный поиск или что-то ещё, что уменьшает число операций.

5. Когда использовать

Всегда. Правда.

Сложность прикидываем до того, как пишем основной код.

6. Когда НЕ использовать

Практически никогда нельзя про неё забывать.

Даже если алгоритм правильный, он может просто не пройти по времени.

7. Суть

Нас интересует, как число операций растёт вместе с размером входа.

Например:

один цикл — O(n)

два вложенных — O(n²)

сортировка — O(n log n)

8. Формулы / что держать в голове

Основные оценки:

O(1)
O(log n)
O(n)
O(n log n)
O(n²)
O(n³)
O(2ⁿ)
O(n!)

9. Частые паттерны

Один проход — O(n)

Сортировка + проход — O(n log n)

Два независимых прохода — O(n)

Два вложенных — O(n²)

Перебор всех подмножеств — O(2ⁿ)

10. Что рядом

· Binary Search → O(log n)
· Sort → O(n log n)
· Prefix Sum → O(n) на построение, O(1) на запрос
· Two Pointers → обычно O(n)
· BFS/DFS → O(V + E)

11. Ограничения

Big O сам по себе не говорит, сколько именно секунд будет работать код.

Он показывает порядок роста.

Константы тоже важны, не стоит про них забывать.

14. Где обычно косячат

· смотрят только на количество строк;
· забывают про вложенные циклы;
· забывают, что сортировка тоже что-то стоит;
· лепят O(n²) при n = 2 * 10⁵;
· думают, что map или set работают как массив по скорости.

15. Мини-пример

Если:

n <= 2 * 10⁵

то:

for (int i = 0; i < n; i++)
for (int j = 0; j < n; j++)

это O(n²) и почти наверняка слишком медленно.

16. Что потренировать

· определить сложность готового кода;
· подобрать алгоритм под ограничения;
· прикинуть число операций;
· понять, пройдёт ли O(n²) при данном n.
