
# Complexity — Оценка сложности

## 1. Название

Оценка временной и пространственной сложности алгоритма.

## 2. Что делает

Позволяет заранее понять, насколько быстро будет работать алгоритм
и сколько памяти он потребует.

Главная запись — Big O:

O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ), ...

## 3. Главный триггер

В условии дано большое `n`, и нужно понять:

"Успеет ли мой алгоритм?"

## 4. Как распознать в условии

Сначала смотрим на ограничения.

Например:

n <= 20
→ можно рассматривать O(2ⁿ), иногда O(n!)

n <= 1000
→ O(n²) может быть нормально.

n <= 2 * 10⁵
→ обычно нужно что-то около O(n log n) или O(n).

n <= 10⁹
→ O(n) уже слишком много, обычно ищем математику,
бинарный поиск, формулу или другой способ уменьшить количество операций.

## 5. Когда использовать

Всегда.

Оценка сложности нужна до написания основного алгоритма.

## 6. Когда НЕ использовать

Практически никогда нельзя полностью игнорировать сложность.

Даже если алгоритм кажется правильным, он может не пройти
по времени.

## 7. Основная идея

Нас интересует, как количество операций растёт вместе с размером входа.

Например:

один цикл:
O(n)

два вложенных цикла:
O(n²)

сортировка:
O(n log n)

## 8. Формула / инвариант

Главные оценки:

O(1)
O(log n)
O(n)
O(n log n)
O(n²)
O(n³)
O(2ⁿ)
O(n!)

## 9. Типичные паттерны

Один проход:
O(n)

Сортировка + проход:
O(n log n)

Два независимых прохода:
O(n)

Два вложенных прохода:
O(n²)

Перебор всех подмножеств:
O(2ⁿ)

## 10. Связанные алгоритмы

- Binary Search → O(log n)
- Sort → O(n log n)
- Prefix Sum → O(n) построение и O(1) запрос
- Two Pointers → часто O(n)
- BFS/DFS → O(V + E)

## 11. Ограничения

Сама оценка Big O не говорит точное количество секунд.

Она показывает порядок роста.

Константы тоже имеют значение.

## 14. Типичные ошибки

- смотреть только на количество строк кода;
- забывать о вложенных циклах;
- забывать стоимость сортировки;
- использовать O(n²) при n = 2 * 10⁵;
- считать `map` или `set` обычным массивом по сложности.

## 15. Мини-пример

Если:

n <= 2 * 10⁵

то:

for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)

даёт O(n²) и почти наверняка слишком медленно.
